# Android Systems Atlas 需求规格

首次记录：2026-11-08；设计与呈现规范归整：2026-11-17。依据：本次会话中用户明确要求及后续修订。
状态：本地双语大框、术语解释和限定场景的普通PCM播放样板已实现；其他领域及其他场景逐项推进。后续专题统一遵守[专题设计与呈现规范](CONTENT-AND-DIAGRAMS.md)及[编写与验收模板](TOPIC-TEMPLATE.md)。文中的验收标准不代表所有专题已经通过，实际范围见对应验证记录。

## 1. 产品目标与读者

建设一个面向新手的 Android 系统技术学习网站，支持中文和英文，以图解为主要教学方式。帮助读者先理解整体架构、层级职责及调用关系，再按技术领域深入学习。

核心读者包括有 Linux 或软件开发基础、但不熟悉 Android 系统的开发者。专业术语首次出现时应解释；不能要求读者先理解大量 Framework、HAL 或厂商缩写才能读懂首页。

尽可能覆盖 Android 系统主要技术领域，以明确的知识目录表达覆盖范围，不宣称穷尽所有 Android 技术点。应用 API 用于说明系统入口；完整的应用 UI 开发课程不作为当前核心目标。

## 2. 用户明确要求

- 支持中英双语言。
- 图解为主，界面清晰，适合新手入门及了解整体架构。
- 可按技术领域学习。
- 图中尽可能明确标记数据流向、传递内容和通信方式，支持可交互、可播放的过程演示。
- 以最新正式发布的 Android 版本为讲解基线；子系统先讲通用机制。
- 讲差异时同时关注两个独立维度：Android 对应版本之间的差异，以及设备形态之间的差异。
- 平台与版本差异栏目只讲大的区别；子领域的版本差异、架构变化放在按领域学习中。
- 弃用的技术也要说明，并解释替代方案和适用范围。
- Google 官方资料为主，能够获取的高通资料为辅。
- 全部内容重新撰写，全部教学图重新绘制；保留依据及来源。
- 不需要练习。

## 3. 信息架构

### 3.1 整体架构入门

以全局架构图为入口，解释 App、Framework、运行时与原生组件、系统服务、HAL、内核与驱动、硬件之间的职责关系。

必须区分职责层级、运行进程和通信机制，不能把架构画成所有请求都必须逐层经过的固定流水线。以典型场景连接全局结构与实际调用，例如启动应用、播放声音、打开相机、显示一帧、处理输入。

### 3.2 按领域学习

每个领域先讲通用机制，再说明版本与形态差异；同一领域内组织浅层概览与进一步阅读内容。

建议覆盖目录（具体拆分在内容设计时确定）：

| 领域 | 内容范围 |
| --- | --- |
| 系统结构与 IPC | 层级、进程、服务、Binder、AIDL、JNI、共享内存和其他通信机制 |
| Framework 与运行时 | 系统服务、组件生命周期、进程、窗口、包与资源管理、ART、Zygote |
| HAL 与兼容性 | 接口边界、AIDL/HIDL 演进、Treble、VINTF、兼容性要求 |
| 内核与 BSP | GKI、驱动、设备树、内存、调度、DMA、硬件适配 |
| 音频 | 播放、录音、策略、混音、HAL、驱动、DSP 和设备路由 |
| 图形显示 | 渲染、buffer、同步、SurfaceFlinger、显示合成 |
| 相机与媒体 | 请求和结果、图像数据流、HAL、ISP、编解码、DRM、音画同步 |
| 输入与传感器 | 输入分发、触摸、按键、传感器及反馈 |
| 连接与通信 | 网络、Wi-Fi、蓝牙、蜂窝、定位、USB、NFC |
| 存储 | 分区、文件系统、访问模型、加密与数据管理 |
| 电源与性能 | 唤醒、休眠、调度、温控、内存压力和性能观测 |
| 安全 | 沙箱、权限、SELinux、可信启动、密钥与可信执行环境 |
| 构建、启动与更新 | 源码组织、构建、镜像、启动链、init、OTA、模块更新 |
| 调试与系统验证 | 日志、dumpsys、Perfetto、故障定位、兼容性测试体系 |

这里的“系统验证”是 Android 工程知识，不是给读者出的练习或测验。

### 3.3 平台与版本差异

只承担跨领域、全局层面的比较：重大 Android 架构演进、设备形态的总体定位与架构差异、高通整体平台组成及其与 AOSP 的关系。领域细节通过链接进入对应章节，避免重复维护。

高通保留独立专题入口；音频、相机、显示等具体高通实现，应在相关领域讲解并从专题链接进入。

## 4. 差异说明规范（重点）

### 4.1 Android 版本差异

每一项有证据支持的差异都应说明：

1. 涉及哪些 Android 版本，必要时精确到源码标签、接口版本或配置条件。
2. 之前是什么机制，之后发生什么变化，变化影响哪个组件或调用关系。
3. 是新增、行为变化、架构调整、弃用还是移除；不能将这些状态混为一谈。
4. 已弃用技术的替代方案，以及旧设备/升级设备上可能继续存在的条件。
5. 官方文档或对应版本源码依据；无法确定引入版本时明确标为未确认，不猜测。

版本说明应出现在相关图旁或相关章节中，不能只在全站版本页笼统提一句。区分 Android 平台版本、HAL 接口版本、内核版本及厂商 BSP 版本，不能默认一一对应。

### 4.2 设备形态差异

以通用机制为正文主线，结合可靠资料说明手机、平板/大屏/折叠屏、车载、电视、可穿戴等形态之间的实际差别。具体内容受资料可得性约束，不要求为每章强行制造差异。

差异说明应回答：哪些机制共享；哪些组件、策略、输入输出、硬件能力、权限或使用场景不同；差异如何影响本领域的架构或链路。设备形态、Android 版本和芯片供应商是不同维度，不互相替代。

比较时尽量使用相同 Android 版本；若资料版本不同，必须标明，避免把版本变化误认为形态差异。没有确认的差异在编写/审查记录中注明“尚未确认特定差异”，不能声称所有形态完全相同；影响当前机制理解的适用条件在正文或图旁就近说明，不制造空比较章节或产品状态提示框。

### 4.3 厂商实现差异

高通是通用 AOSP 讲解的补充。说明公开资料对应的芯片/产品系列、软件分支、运行系统和可验证范围。不得把 Qualcomm Linux、上游 Linux 或特定开发板实现直接等同于 Android 手机 BSP；不得把单个高通方案推广到所有高通产品。

## 5. 版本基线管理

开始内容编写时核实 Google 最新正式发布的 Android 版本，记录核验日期和具体参考标签/分支。不沿用早期 Android 15/16 限定。2026-11-08首批核验确定Android17正式大版本与 `android-17.0.0_r1` 源码锚点，证据及尚未完成的逐文件核验见 [CONTENT-BASELINE.md](CONTENT-BASELINE.md)。

预览版或开发分支单独标注，不混入正式版主线。后续升级基线应对内容和图逐项核验，不能只修改首页版本标识。历史版本只在理解演进、兼容性、弃用与替代关系需要时展开。

## 6. 来源与原创表达

优先使用 source.android.com、developer.android.com、AOSP 对应版本源码及 Google 官方发布说明。高通补充使用可访问的官方文档、官方公开仓库及明确标识的相关上游资料。

第三方学习项目用于比较组织方式与发现线索，不作为未经核验的技术结论依据。每篇保留来源链接、适用版本、核验日期；关键差异应有直接证据。重新撰写与绘图不等于取消引用，也不等于可以无视第三方素材许可。

不虚构私有接口、BSP 细节、源码路径、支持范围或设备行为。文档/源码核验与设备实测要明确区分，未实测不得写成已实测。

## 7. 双语与图解要求

导航、正文、说明、图例和图中文字均提供中英文，技术标识符保留原名，中英术语保持统一。两种语言表达同一技术事实，版本与形态差异说明不能只在一种语言存在。

图用于解释责任、边界、关系、时序和数据流，不只是装饰。区分控制流与数据流；标明进程边界及必要的通信方式。教学简化必须注明范围，复杂关系按层次拆图。

交互图按 [内容与交互图规范](CONTENT-AND-DIAGRAMS.md) 实施：完整关系图、默认数据方向循环演示与暂停/继续、节点与连线解释、控制流与数据流分看或合看，以及有证据支持的版本/设备场景对比。动画表达方向与逻辑关系，不冒充实测时间、速度或严格串行执行。

语言切换保留当前主题与阅读位置。默认中文、电脑阅读优先并兼容手机，沿用现有预览方式；不为界面简洁随意隐藏必要说明。

## 8. 专题页面通用模板

紧凑标题与一句导语 → 本页目录 → 核心概念与全局位置 → 横纵一体的场景全景图 → 关键机制局部图及必要说明 → Android版本演进 → 设备形态差异 → 有证据的厂商补充 → 集中参考资料。

厂商补充可紧接相关机制；术语在正文、图和解释中就近提供短浮层及完整词条入口。主图只保留一组标题，概念卡片简短，必要技术细节紧随图解直接展示，不随意折叠；目录、配色、动画与全屏沿用统一规范。

模板不要求每一页机械复制空段落；先判断版本、形态、厂商三个维度，有充分依据才展开。技术边界在相关图旁写清，证据表、未完成项与验收记录保留在内部文档。详细规则与可复制稿件见[专题设计与呈现规范](CONTENT-AND-DIAGRAMS.md)和[专题模板](TOPIC-TEMPLATE.md)。

## 9. 范围排除与未定事项

明确不做练习、测验、题库或闯关。旧草稿中的这些功能已被当前需求替代。收藏、笔记、进度、账号、云同步、导出导入并非用户明确要求，不纳入本次确定范围。

现有本地预览采用原生 HTML/CSS/ES modules，后续在现有大框上推进；本轮不要求更换技术栈或重新设计视觉。具体文章拆分按内容需要逐步确定，公开部署位置仍未定；公开部署不属于本轮文档更新。

## 10. 后续验收标准

- 新手可以从全局图找到主要领域，并解释该领域在系统中的位置。
- 中英切换覆盖导航、正文、图例、图中文字与差异说明，无整段漏译。
- 关键主题有职责图及必要的调用/数据流图，箭头含义和适用场景清楚。
- 每个领域检查 Android 版本差异与设备形态差异两个维度；有差异则具体解释，有信息缺口则明确标注。
- 弃用、移除、替代、兼容残留分别说明，并有版本证据。
- 基线是经核实的最新正式版本；高通资料和主线 Linux 资料边界明确。
- 关键技术结论与图可追溯至官方文档或适用源码；未实测的内容不冒充实测。
- 页面目录清晰、链接可用，桌面及手机阅读与图解交互经过浏览器验证。
- 不出现练习、题库等被排除功能；不以历史原型或历史验证记录作为当前交付验收。

## 12. 内容深化与本轮确认（2026-11-08）

用户接受内容建议，并进一步要求图中清楚表达数据流向、支持交互动画。细化规范见 [内容与交互图规范](CONTENT-AND-DIAGRAMS.md)。
