# 专题设计与呈现规范

更新日期：2026-11-17。适用于所有领域专题、同一领域的后续场景及高通补充。依据用户已确认的图解、术语、交互和阅读布局要求整理；普通 PCM 播放页是呈现样板。

本文件规定后续设计、编写、实现与审查必须遵守的规则，不代表所有专题已经实现或验收。需求见 [REQUIREMENTS.md](REQUIREMENTS.md)，决策沿革见 [DECISIONS.md](DECISIONS.md)，新专题从 [TOPIC-TEMPLATE.md](TOPIC-TEMPLATE.md) 开始。术语的详细规则由 [GLOSSARY-DESIGN.md](GLOSSARY-DESIGN.md) 维护。

## 1. 使用规则与复用边界

- 必须沿用：图解优先、中英双语、横纵一体的关系表达、必要技术深度、原位术语解释、统一视觉与图操作、来源可追溯。
- 按领域调整：典型场景、组件、必要的局部机制、目录名称、版本/形态/厂商差异及有意义的动画。不能机械复制音频组件或凑齐空章节。
- 必须重新核验：每个专题的技术事实、源码版本、接口、组件归属、数据路径和差异。音频的浏览器检查或技术核验不为其他领域背书。
- 用户有新的明确要求时，同轮修订本规范、对应专门规范与决策；影响范围时同步实施计划。先消除冲突，再实施，不保留两套相反的现行规则。
- 历史图稿和验证记录只支持其记录的版本与范围；完成状态见对应专题记录，不在规范中滚动堆积“本次落地”说明。

## 2. 网站框架与阅读路径

侧栏顺序固定为：**术语解释 → 架构全景 → 按领域学习 → 平台与重大变化 → 高通平台专题 → 资料与阅读说明**。默认首页仍是架构全景，术语入口靠前不意味着读者必须先背词典。

领域统一归入“按领域学习”，子页保留该导航高亮。保持左侧主导航、顶部当前位置/搜索/中英切换、主体阅读区；手机使用菜单与单列正文。不得恢复侧栏重复领域快捷入口、宣传语或 GitHub 入口。

全局入门区分别解释三种视角，名称与专题保持一致：

| 视图 | 回答的问题 | 不能造成的误解 |
| --- | --- | --- |
| 职责架构图 | 谁负责什么 | 所有请求必须逐层通过 |
| 进程/执行边界图 | 组件在哪里运行 | 一个职责层就是一个进程 |
| 场景关系图 | 一次操作怎样协作 | 跨层就一定是跨进程或严格串行 |

专题内用简短说明把当前问题放回全局位置，不要求每页再重复三张全站总览。

## 3. 专题页面的组织顺序

~~~mermaid
flowchart TB
    A[返回领域目录 · 紧凑标题与一句导语] --> B[本页目录]
    B --> C[核心概念 · 技术解决什么问题]
    C --> D[场景全景图 · 纵向归属与横向协作]
    D --> E[关键机制局部图 · 必要短文]
    E --> F[Android 版本演进]
    F --> G[设备形态差异]
    G --> H[有证据的厂商补充 · 可放在对应机制附近]
    H --> I[集中参考资料]
~~~

1. **标题区**：领域分类、一个主标题、一句介绍。图标和状态信息从属标题，避免大图标、巨大标题和多层留白把主图推远。
2. **本页目录**：名称短且对应实际章节。宽屏均匀排列，中小屏规则换行；所有入口直接可见，不出现孤立的最后一项。跳转后标题不能被顶栏遮住。
3. **核心概念**：先用短句建立理解主线，必要时用两三个概念对照。例如音频区分控制与数据；其他领域选择自己的关键区别，不强行套用这两个标题。
4. **场景全景图**：先让读者看到系统位置和参与者如何协作。图内只保留一组主标题与简短场景说明，取消图内外重复标题。
5. **必要细节**：沿主图的关键边界展开局部图，较长的职责、连接与反馈说明紧随对应图出现。必要内容直接展示，不藏入折叠面板。
6. **三类差异**：Android 版本、设备形态、厂商实现分别判断。厂商说明可紧接相应机制，也可设小节；不必为了固定顺序远离讲解位置。
7. **参考资料**：集中列出本页实际引用的资料；节点、连线、术语处继续保留就近入口。

无可靠差异时不造空白比较图；在编写/审查记录中写清检查过哪个维度和缺口。影响读者理解的适用条件必须在图旁说明。

## 4. 内容深度与说明文字

### 4.1 保留哪些细节

以一个明确场景解释实际机制。对关键子系统，按适用性回答四个问题：

| 问题 | 必要信息 |
| --- | --- |
| 数据在哪里 | 输入/输出、载荷、缓冲、读写方，数据本体还是引用 |
| 谁决定与配置 | 策略、资源选择、连接、初始化与运行控制各由谁负责 |
| 谁实际执行 | 软件组件、驱动、硬件、固件的分工及相互调用 |
| 如何反馈 | 状态、错误、完成事件或消费位置，通知谁、说明什么 |

不存在持续数据或反馈的概念不硬编这类机制。主图省略的细节应能在局部图、节点解释或完整术语中找到；不能仅用“设备相关”省略一整段理解所必需的后端。

音频驱动样板展开 HAL 用户态后端、ALSA PCM、播放缓冲、ASoC 协作、驱动、DMA 硬件、数字接口与 Codec/DAC，是该场景的具体例子。其他领域按相同问题选择自己的必要细节，不能照搬这条物理链路。

不为增加深度堆寄存器、完整回调表、无关函数名或历史。加入一个细节，应能说明它如何改变职责、数据、配置、执行或反馈的理解。

### 4.2 怎样写与怎样呈现

- 先说对象是什么、负责什么，再解释机制与边界。使用短段落、具体动作和统一名称；必要术语可以随时查看。
- 图后也以关系图、缓冲示意、局部放大或独立方案对照为主，短文补充机制与误区。不能把长段正文分装进许多长文字卡片就称为图解。
- 数值示例标明假设、单位和公式；缓冲时长、通知粒度、处理完成与用户实际感知不能混写。例如消费进展不能简称为含义不明的“进度”。
- 教学范围用与内容有关的短说明表达，如“板载直连示例”“上游 Linux 机制对照”。不恢复“本页只是示范”“内容待补”“资料核对不等于设备实测”等产品状态提示框；完成范围和未验证事项写入项目记录。技术边界仍必须保留。
- 不在正文或图后设置“点击节点查看”“Tab选择、Enter/空格打开”“下划线术语可点击”等操作教学提示块，也不保留空白占位。通过组件标签、按钮名称、状态和可访问性属性表达操作；节点的实际职责说明在用户选择后于旁边悬浮展示，点击、键盘、触屏与读屏支持继续保留。
- 本站重述不能标成官方原文；直接引用须可核对，来源不能被文案简化掩盖。
- 不增加练习、题库、闯关或未经要求的账号、笔记、学习进度功能。

## 5. 图的结构、归属与连线

### 5.1 主图必须横纵一体

纵向表达职责或已核实的执行边界，横向表达同层组件协作。连线连接实际参与者端点，允许跨层和转折；不能用互不相连的大卡片、孤立箭头列表替代关系图。

区分职责、进程、用户态/内核态、硬件与固件环境；不同含义的边框应直接写明。只在来源支持时标明具体进程、线程或厂商归属。

队列、共享内存、接口和用户态库按实际含义放置：

- 共享通道是双方的通信机制，不凭位置新增“架构层”或进程。
- 实现内部的访问库/后端归入实现边框或子区域，不与其所属层并列。
- 驱动是软件，硬件执行单元另画；配置/绑定对象不串进样本路径。
- 互为替代或独立的方案分区/并排对照，不画成彼此的下一站。

### 5.2 连线的统一含义

| 关系 | 颜色 | 线型 | 在线上至少说明 |
| --- | --- | --- | --- |
| 数据/信号 | 绿色 #25756b | 实线＋箭头 | 载荷、方向及必要的读写/访问方式 |
| 控制/配置/建立关系 | 琥珀色 #a16c2c | 虚线＋箭头 | 动作、请求或配置对象；必要的通信方式 |
| 响应/回调/反馈 | 蓝色 #527d99 | 点线＋箭头 | 返回的状态、事件、描述符或消费信息 |
| 组成/关联 | 中性灰绿 | 非定向关系线＋文字 | 归属或关联含义，不伪装成数据传输 |

图例、概念卡片、局部图和术语图保持相同语义，不只靠颜色区分。请求和返回分别画；无说明的双向箭头不用于代替两个不同动作。

必须区分数据字节传输、共享缓冲读写、句柄/地址/描述符传递以及信号形态变化。不得从“共享内存”自动推断端到端零拷贝，也不能把命令消息画成携带全部样本。

线交叉尽量避开；无法避免时明确“交叉不连接，以端点为准”。标签避免压住节点、箭头及其他文字。并发、异步和持续流不被错误串行化；教学编号不能冒充真实执行时序。

### 5.3 信息分层

图上直接显示重要方向、载荷、归属与场景限定。节点/连线可进一步解释职责、输入输出、通信机制、易混淆点和来源，不能要求读者先点击才知道箭头在传什么。

组件说明先回答“它是什么、做什么、处理什么、与谁协作”，再补当前场景与必要边界；不能用“本例选择什么”“不代表所有路径”等提醒替代职责。每条连线解释必须说明这一条连接的动作、载荷及通信/读写方式，不能只重复颜色、线型、起终点名称或所有连线通用的免责声明。术语与图中语境定义必须一致，来源逐项支持具体陈述；结构/渲染检查通过不能充当内容审校通过。

局部图节点同样支持点击、Enter/空格查看解释。组合节点可解释本图语境，不强行映射成含义不同的单个词条。图与节点说明中的新词同样纳入术语。

节点及可解释连线采用点击固定的原位说明卡片，主图与局部图统一使用；不再把选中说明放在图底部而要求读者向下寻找。悬停保留视觉强调，不新增经过即弹出的组件说明。卡片保留职责/载荷、必要边界和真实来源标题，正文术语继续可查。

卡片优先放在节点侧面，空间不足时放在上/下方并限制在可见视口内；长内容内部滚动，关闭按钮保持可达。点击不改变页面阅读位置。点空白、再次点击同一节点、关闭按钮或Esc可关闭；键盘激活后可进入卡片，关闭按钮/Esc回到原节点，外部点击不抢回焦点。全屏内卡片在图窗中显示，术语/完整释义优先逐层关闭。语言切换、筛选、重绘或离页清理失效卡片；滚动时跟随可见锚点，锚点移出可见区域后关闭且不强制回滚。

## 6. 动画、图操作与全屏

### 6.1 动画用于帮助读懂方向

- 场景关系图默认完整显示，已核实的数据/信号路径默认缓慢循环流动；光点沿图中实际连线运行。
- 控制建立、路由配置、响应与回调默认静态，聚焦时可强调。不得循环开流/初始化，或暗示每批数据都重新配置硬件。
- 驱动及厂商局部图可沿用克制的数据方向动画，离开视口暂停；不让多张图同时抢占注意。完整术语的小关系图默认静态，组成/概念图不为形式统一强加流动。
- 动画不表示真实速度、耗时、吞吐、包数量或严格时序。暂停后箭头、标签和关系仍然完整可读。
- 遵循减少动态效果设置，默认静态；后台暂停，返回时保留用户此前状态。用户暂停后，筛选或选择节点不能擅自恢复动画。

### 6.2 图操作分组

路径筛选在左，动画与放大在相邻操作组；窄屏整组换行，按钮不散落在无关位置。混合数据与控制的场景图提供完整关系/数据/控制与返回视图；没有相应关系的图不凑无用筛选。

只保留有用操作：**暂停动画/继续动画、路径筛选、放大图/退出全屏、节点与连线解释**。不恢复上一步、下一步、重播、自动阶段跳转或四阶段控制面板。

### 6.3 放大即全屏查看

放大覆盖整个浏览器内容区域，无需切换操作系统全屏。使用模态图窗，背景不可交互或滚动；顶部固定工具栏保留退出入口。图保持二维结构，内部按需要上下/左右滚动。

全屏内筛选、动画、组件说明、短术语浮层与完整解释保持可用。切换视图或选择组件不退出全屏、不重置画布滚动。Esc 优先关闭最上层解释，再退出图窗；退出回到原阅读位置与放大按钮。

## 7. 术语解释

沿用 [GLOSSARY-DESIGN.md](GLOSSARY-DESIGN.md) 的两层阅读：

| 层次 | 展示内容 | 阅读目的 |
| --- | --- | --- |
| 正文原位短浮层 | 术语、全称/名称、短定义、一个关键边界、完整解释入口 | 看懂当前句子，继续原位置阅读 |
| 完整词条 | 定义、架构位置、原创关系图、三个关键问题、范围、来源与核对信息 | 理解它如何参与系统工作 |

覆盖缩写、类/服务、库、驱动/源码组件、接口/协议、缓冲、数据格式和基础机制。q6asm、tinyalsa、mmap 等也需要解释；源码名没有可靠全称时保留原名，不反向编造全称。

鼠标悬停约 **350ms** 后显示；提前移出、切换词语、滚动、离页或重绘取消待显示任务。点击固定、键盘聚焦即时显示，支持触屏与移入浮层阅读。固定解释不被鼠标经过其他词语替换；Esc/外部点击关闭，关闭后保留阅读位置与合理焦点。

短释义、词典卡片和完整解释共用词条数据，图中上下文解释不得与其矛盾。正文中的真实来源链接保持链接用途，不被术语匹配覆盖。原位悬浮指网站能力；普通 Markdown 文档保留文字说明与引用。

## 8. 视觉、排版、双语与响应式

### 8.1 视觉体系

| 用途 | 当前参考值 |
| --- | --- |
| 正文/主标题 | 墨绿 #203b36 |
| 侧栏 | 深绿 #183c35 |
| 页面底色 | 暖白 #f8f7f2 |
| 次级文字 | #596760 |
| 分隔线 | #dcded5 |
| 主操作 | #174d43 |

数据、控制和响应色见第5节，不能随卡片审美交换含义。保持安静底色、清晰字重、轻边框和有限圆角；不新增大面积装饰、重复状态条或无关宣传信息。

### 8.2 阅读排版

以当前音频页为尺寸起点：正文约15–16px、行高1.75–1.9；主标题桌面34px/手机28px；章节标题约24px，手机约21–22px；紧凑卡片标题约18px。它们是复用参照，具体组件按实际文字与视口验证，不要求所有标签使用同一字号。

主图尽早进入阅读视野，优先去除重复标题、过大图标与累计留白。较长技术说明放在对应图后可见位置；不通过缩小正文、压缩行距或折叠内容换取紧凑。对照卡片解释相近深度的问题，避免一侧长篇、一侧空白。

正文限制过长行宽，图解利用可用内容宽度。图中文字不能整体缩成无法阅读的小字；空间不足保留图内滚动和全屏入口。长源码名、全称和来源标题可完整换行，不裁切、不省略。

沿用音频专题的顶部目录、图框、工具栏、图例和交互样式。主图占满正文列，桌面常用宽度默认可看到横向两端；窄屏达到最小可读尺寸后，画布在图框内横向滚动，图旁提示滚动或全屏查看。

### 8.3 双语和小屏

导航、目录、正文、图中文字、图例、工具栏、浮层、完整释义、范围和差异均成对维护。技术标识符不翻译；真实文档标题保留原文。两种语言表达同一事实，不能英文遗漏限制、中文独有新结论。

切换语言保留主题与阅读位置，清理失效浮层锚点。英文长度增加时允许换行，不以缩字或裁切解决。手机采用单列阅读；本页目录规则换行，操作组保持完整，图继续二维呈现，只允许必要的图内横滚，禁止整页横向溢出。

键盘可访问目录、图操作、节点、连线与术语，有可见焦点、正确选中状态及关闭后回焦；为图保留能表达关系的文字说明。不能把颜色或运动作为唯一的信息来源。

## 9. 差异、版本基线与来源

### 9.1 三个维度分别判断

| 维度 | 必须回答 |
| --- | --- |
| Android 版本 | 变化从哪个版本开始、之前/之后是什么、影响哪些节点/连线；新增/弃用/移除分别说明，旧实现何时仍可存在、替代方案是什么 |
| 设备形态 | 共享什么机制、哪些组件/策略/能力不同、对场景关系有何影响；尽量同版本比较，不把版本变化当形态差异 |
| 厂商实现 | 来源属于哪个产品/系列、OS、分支或上游版本；与通用主线的关系、证据能支持到哪里 |

全局栏目只讲重大跨领域变化，子系统演进留在对应专题。差异尽量定位到变化的组件、边界和连线；有证据才提供场景切换，不凑全版本×全形态组合。

Android 版本、HAL 版本、内核版本和 BSP 分支不能默认一一对应。Linux 上游或 Qualcomm Linux 资料不等于 Android 出货 BSP；不能把两套独立高通 DSP 机制串成同一条必经链。

### 9.2 资料核验与引用

- 编写时按 [CONTENT-BASELINE.md](CONTENT-BASELINE.md) 核实正式版本与源码锚点；日期变化不能自动成为技术基线升级。不直接复制音频的版本号当作新专题已核验的依据。
- Google 官方文档、对应版本 AOSP 源码与发布资料为主，高通可靠公开资料为辅。第三方学习项目只作为组织参考或线索。
- 版本结论使用明确 tag/不可变修订。仅作当前主线参考的可变分支必须说明用途，不能冒充正式版证据。官方概览的历史术语也需结合目标版本专门文档核对。
- 记录来源URL、真实标题、适用版本/标签、核对日期、读取状态、支持的结论与图节点/边。未读、读取失败、旧版本材料和设备实测分别记录；访问失败不证明文件不存在。
- 可见链接显示实际文档标题，源码显示文件名及版本，不使用“查看依据”“查看官方依据”等泛化文字。编写时核对并保存标题，不在用户阅读时联网抓取。
- 页尾汇总正文、主图节点/连线与局部解释实际引用的资料，按URL去重。同一概念的主图与词条同步维护版本；词条的延伸阅读可保留在完整解释内。
- 文字和图重新撰写绘制，保留来源及许可边界；不把本站释义包装为官方原文。不能以来源数量或官方首页链接替代对具体结论的支持。

## 10. 实施与验收

按“场景与资料 → 页面/图稿 → 实现 → 内容复核与浏览器检查 → 记录交付”推进。内容复核和呈现验收分别完成，不能等用户指出问题才首次核验关键机制；发现问题先修正再交付。

新专题使用模板中的清单，至少检查下列项目：

| 检查项 | 通过标准 |
| --- | --- |
| 问题与范围 | 初学者能知道本页解释什么、当前选了哪条路径；适用条件在对应图旁可见 |
| 必要深度 | 关键数据/缓冲、配置、执行和反馈有位置；没有用泛称掩盖关键机制，也无无关细节堆砌 |
| 主图 | 横纵一体、端点真实、归属清楚；字节/引用、控制/反馈、软件/硬件不混淆 |
| 局部图 | 补充主图所需细节；独立方案不串联；数值有假设与量纲 |
| 术语 | 正文与全部图内陌生概念可就地理解；短释义、完整解释、双语和来源一致 |
| 差异 | 分别检查版本、形态、厂商；已确认结论有证据，未知项不填造 |
| 引用 | 来源与结论/图对应，版本明确，标题可读，页尾集合完整 |
| 可读性 | 标题、目录、核心概念、主图与细节顺序清楚；无重复大标题、长文字墙和无意义提示框 |
| 浏览器交互 | 目录定位、筛选、暂停/继续、全屏滚动与退出、术语、键盘、回焦及语言切换正常 |
| 动态与小屏 | 静态/减少动态效果下可读；无整页横向溢出；按钮不裁切，图可滚动查看 |
